# Headroom Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship a public, reproducible Uniswap v4 gas-responsive LP-fee hook with one nominal discount allowance per transaction.
**Architecture:** BaseHook validates supported dynamic pools, returns per-swap LP fees and reserves ETH-denominated discounts in EIP-1153 transient storage. Tests use a real PoolManager and multi-swap settlement helpers; a separate Anvil check proves transaction reset.
**Tech Stack:** Solidity 0.8.26, Cancun, Foundry, pinned v4-core and OpenZeppelin hooks.
**Spec:** ../specs/2026-11-13-headroom-design.md

## Global Constraints

- New isolated repository in dynamic-fees-hook; leave first-hook unchanged.
- Base fee 3000, floor 500 millionths; reference gas 100000; basefee cap 100 gwei.
- Only native ETH or configured WETH exact-input trades qualify.
- One allowance per hook instance per transaction, shared across pools and callers; conservative requested-input reservations.
- No oracle, owner, custom settlement in production hook, hook fee or rebate transfer.
- Public GitHub delivery; no funded public-chain deployment or quest-form submission.
- Keep workspace RESEARCH.md updated. The latest user request authorizes implementation; execute inline without another approval handoff.

## File responsibilities

- src/HeadroomHook.sol: pool validation, pricing, transient reservations and quote view.
- test/HeadroomHook.t.sol: actual pool fee application, eligibility, depletion, rollback, arithmetic properties.
- test/utils/HeadroomFixture.sol: local pool/mock-token/liquidity setup and batch helpers.
- script/DeployHeadroom.s.sol: permission-valid CREATE2 deployment.
- script/LocalDemo.s.sol and scripts/check-transactions.py: fresh Anvil deployment and separate same-block transaction verification.
- README.md, docs/verification.md, .github/workflows/test.yml: reproduction, limitations and CI.
- foundry.toml, foundry.lock, .gitmodules: compatible locked dependency configuration.

## Review Focus

- Zero remaining budget cannot trigger reinitialization: exhausted-budget multiple-swap test.
- Changing caller or pool cannot mint another budget: actual swaps through different routers/pools.
- Partial or empty execution consumes the requested-input reservation: explicit bounded fill and empty-pool tests.
- Rounding and int256.min cannot overflow or overreserve: fuzz plus extreme-amount quote tests.
- A new block is not a new transaction: same-transaction block-change check and real separate same-block Anvil transactions.
